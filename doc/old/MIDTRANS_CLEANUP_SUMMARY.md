## Security Considerations

### Current Implementation
- Admin UI forms **allow** input of Paddle API keys and webhook secrets
- Helper text **recommends** storing secrets in environment variables
- This matches the previous Midtrans implementation pattern

### Recommended for Production (Phase 8)

**Hybrid Approach:**
1. **Environment Variables (Sensitive):**
   - `PADDLE_API_KEY` - API authentication key
   - `PADDLE_WEBHOOK_SECRET` - Webhook signature verification

2. **Database (Non-Sensitive):**
   - `vendor_id` - Public Paddle Vendor ID
   - `environment` - "sandbox" or "production"
   - `webhook_url` - Public webhook endpoint URL

3. **Implementation:**
   When implementing Paddle service layer (Phase 8), configure code to:
   ```typescript
   const paddleConfig = {
     apiKey: process.env.PADDLE_API_KEY,  // From env
     webhookSecret: process.env.PADDLE_WEBHOOK_SECRET,  // From env
     vendorId: dbConfig.vendor_id,  // From database
     environment: dbConfig.environment  // From database
   };
   ```

This ensures sensitive secrets never touch the database while maintaining flexibility for non-sensitive configuration.
